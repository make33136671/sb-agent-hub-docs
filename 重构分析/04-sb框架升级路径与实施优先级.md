# 阶段四：sb 框架升级路径与实施优先级

> 日期：2026-08-20
> 依据阶段一~三的分析，给出可执行的重构路径。

---

## 1. 总体策略：彻底切换（无过渡期）

```
【现状】OpenIM = 消息通道/实时信令
【目标】sb-framework 底座 + 框架模块 Sb.Framework.Chat.Realtime（SignalR/WS）
【方式】一次整体切换，不保留双轨/兼容垫片

阶段0  M0 底座对齐 sb-framework（✅）
   ↓
阶段1  后端彻底去 OpenIM（删服务/双轨/垫片/配置，业务直接用 Realtime，访客改签 JWT）（✅）
   ↓
阶段2  前端切换（openim-core → SignalR client）（⏳）
   ↓
阶段3  移除 OpenIM 部署/文档 + 整体回归
```

---

## 2. 分阶段实施路径

### 阶段 0：后端基础设施对齐 sb-framework（✅ M0 完成）
- ✅ `agent-api` 迁移到消费 `sb-framework` NuGet 包（`AddSbFramework`/`UseSbFramework`）。
- ✅ 客服特有配置（OpenIM 等）独立为 `AgentOptions`；`ExcludeControllers` 排除框架内置 20 个 Controller 保留客服定制。
- ✅ `installed.lock`、StaticWebAssets 关闭、自建 `ICacheService`/`JwtToken` 补注册。
- ✅ 全解决方案 0 错误；`/health` 200；框架 `sb_*` 表自动建。
- 详见 `08-M0底座迁移方案.md`。

### 阶段 1：后端彻底去 OpenIM（✅ 完成）
- ✅ 删除 5 个 `OpenIm*Service`、`OpenImTransport`、`IImTransport`、`RealtimeTransport`、`OpenImModels`、`OpenImTests`、`ImTransport` 开关、`OpenIM` 配置。
- ✅ 业务服务（ChatAuthService/KefuService/ConversationService/ChatAuthController）直接依赖 Realtime 模块服务。
- ✅ 访客改签 JWT（复用 JwtAdmin 验签 + ChatUserId/role=visitor claims）。
- ✅ `chat_rt_*` 5 表建立；全解决方案 0 错误；启动通过。
- 详见 `09-彻底去OpenIM切换方案.md`。

### 阶段 2：前端切换（⏳ 待做，1-2 周）
- **动作**：
  1. `openim-core-js` 内部把 `@openim/client-sdk` 换成 SignalR client（`@microsoft/signalr`），**保持对外 API/事件名不变**（`login/on('message:received')/getHistory` 等）。
  2. 移除 `cacheGuard`/`fixSdkCacheAfterSync`/`patchFetchForOpenIM` 等 SDK hack。
  3. `agent-chat`、`agent-widget-js`、`agent-widget-vue` 仅换底层，接口不变；`openim-chat-ui-js` 纯 UI 完全复用。
  4. 顺带修复 B3（XSS）。
- **关键**：对外契约（事件名/消息模型）保持稳定是降低前端改动量的核心。

### 阶段 3：移除 OpenIM 部署并整体回归（⏳ 待做）
- 下线 OpenIM 服务端；回收 `OpenIM` 配置（已删）；移除 `patchFetchForOpenIM`（前端已换）。
- 测试库补业务数据，真实端到端验证：访客认证 → JWT 连 Hub → 建会话 → 收发消息 → 已读 → 在线 → 转接。

## 3. 优先级与里程碑

| 里程碑 | 范围 | 状态 | 交付 |
|--------|------|------|------|
| M0 | 阶段 0 底座对齐 sb-framework | ✅ | 后端跑在 sb-framework 底座，框架表建立 |
| M1 | 阶段 1 后端彻底去 OpenIM | ✅ | 业务直接用 Realtime，`chat_rt_*` 表建立，0 错 |
| M2 | 阶段 2 前端切换（SignalR client） | ⏳ | 前端脱离 OpenIM SDK，三入口共用一次替换 |
| M3 | 阶段 3 移除 OpenIM 部署 + 整体回归 | ⏳ | 完全去 OpenIM，单机部署 |
| M4 | 管理端迁移 `sb-framework-admin`（D12） | ⏳ | agent-admin 统一到 sb 家族基座 |

## 5. 总结

- **去 OpenIM 技术上可行且合理**：后端业务中枢已自建，5 个服务是薄封装可替换；前端虽然耦合深，但只要保持 `openim-core` 对外契约不变，三个前端入口改动很小。
- **最强动因**：OpenIM SDK 稳定性差（cacheGuard 等大量 hack），是弃用最直接理由。
## 5. 总结

- **去 OpenIM 技术上可行且合理**：后端业务中枢已自建，可整体切换为 Realtime 模块；前端保持对外契约，三入口改动小。
- **最强动因**：OpenIM SDK 稳定性差（cacheGuard 等大量 hack），是弃用最直接理由。
- **实现路径**：彻底切换（无过渡期）——M0 底座对齐 ✅ → 后端去 OpenIM ✅ → 前端切换 ⏳ → 移除部署/回归 ⏳。
- **强约束**：`sb-framework-chat` 的 Telegram SDK **不能**替代客服实时聊天；实时通讯以框架模块 `Sb.Framework.Chat.Realtime` 沉淀。
- **建议立即修复**：B1 并发计数只增不减（P0，影响核心可用性）。
