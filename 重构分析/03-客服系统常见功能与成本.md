# 阶段三：客服系统常见功能与实现成本评估

> 日期：2026-08-20
> 成本口径：人日（1 人日 = 8h，含设计 + 开发 + 联调 + 自测；不含 UI 视觉打磨与上线运维）。
> 标注：✅ 已有（盘点现状）/ ➕ 建议新增 / ⭕ 可选增强 / ❌ 明确不做。

---

## 1. 现有功能盘点（agent-api 已实现）

| 功能 | 状态 | 涉及模块 | 备注 |
|------|------|----------|------|
| 访客认证/接入 | ✅ | `ChatAuthService`、`ChatPlatform` | 匿名/实名、平台 Key、域名白名单、接入类型 |
| 实时聊天（文本） | ✅ | OpenIM + `openim-chat-ui-js` | 群聊/单聊双模式 |
| 图片/表情 | ✅ | `ImagePlugin`/`EmojiPlugin` | 走 OpenIM 媒体 |
| 访客排队 | ✅ | `QueueService`、`VisitorQueue`、`QueueCleanupJob` | 含位置/预计等待/取消 |
| 客服分配（路由） | ✅ | `AgentAllocationService` | 轮询/最闲/随机/固定 + 工作时间 + 并发 |
| 管理员接管 | ✅ | 平台 `IsAdminTakeover` | 有 B6 缺陷 |
| 广播模式（多客服监听） | ✅ | `CustomerServiceConfig.EnableBroadcast` | 有 B7 性能问题 |
| 转接 | ✅ | `KefuService.TransferVisitor` | 有 B10 非事务 |
| 访客表单 | ✅ | `VisitorForm` | 可配置字段、必填/可选 |
| 自动回复 | ✅ | `AutoReply` | 含欢迎语/离线自动回复 |
| 离线消息 | ✅ | `OfflineMessage` | 分配离线客服时 |
| 满意度评价 | ✅ | `Satisfaction`、`RatingController` | 有 B11 归属缺陷 |
| 已读回执 | ✅ | OpenIM read receipt | 依赖 OpenIM |
| 客服工作台 | ✅ | `KefuService`（MyVisitors/Status/队列） | 管理端 agent-admin |
| 会话列表 | ✅ | `ConversationService` | 有 B2/B13 缺陷 |
| 聊天记录导出 | ✅ | `DataExport` | Excel |
| 客户端错误上报 | ✅ | `ClientErrorLog` | |
| 配额/套餐/订单/支付 | ✅ | `Quota`/`Order`/`Payment` | SaaS 计费；支付回调签名 TODO |
| 系统设置/菜单/权限 | ✅ | `SystemSetting`/`Menu`/`AdminRole` | 与 sb-framework 高度重合 |

## 2. 建议新增功能与成本评估（按优先级）

| 功能 | 优先级 | 成本(人日) | 说明 |
|------|--------|-----------|------|
| **实时信令层（框架模块 `Sb.Framework.Chat.Realtime`）** | P0 | 15-25（框架）+ 20-30（项目接入） | 替代 OpenIM 的核心；信号协议、消息持久化/分发/在线/已读/历史 |
| **快捷回复/常用语** | P1 | 4-6 | 客服端短语库，管理端可维护；纯前端 + 少量接口 |
| **关键词自动回复（机器人规则）** | P1 | 5-8 | 在现有 AutoReply 上扩展关键词/命中/富文本；后端实现 |
| **会话标签/备注** | P1 | 3-5 | `ChatUser.NicknameRemark/Remark` 已有，补 UI 与接口 |
| **消息审计/敏感词过滤** | P1 | 4-6 | 发送前过滤 + 审计日志；可复用 sb-framework 通用中间件思路 |
| **会话统计报表（量/响应/时长/满意度）** | P1 | 6-10 | Dashboard + 图表；数据在 Conversation/ChatUser/Satisfaction |
| **消息记录全文检索** | P2 | 4-6 | 会话内搜索；落库后 SQL 即可，量大可上 ES |
| **客服忙闲/强制离线** | P2 | 2-4 | 现有 Status + 工作台交互补全 |
| **访客轨迹（来源页/停留/UA/地区）** | P2 | 3-5 | 已采集 pageUrl/referrer，补展示与存库 |
| **工单系统** | P3 | 15-25 | 大功能；创建/流转/状态/结单，独立模块 |
| **AI 客服/大模型应答** | P3 | 15-40 | 依赖模型接入、知识库（sb-framework 有 Qdrant 可复用） |
| **图片/文件/语音消息完整支持** | P1 | 8-12 | 现有 Image 插件 + OpenIM 媒体；去 OpenIM 后需自建上传/下载/缩略图 |
| **桌面/移动 App 端** | ⭕ | 30+ | 需另起客户端项目 |

## 3. 与"去 OpenIM"耦合的功能成本影响

以下功能当前依赖 OpenIM，去 OpenIM 时需一并重构：

| 现有功能 | 去 OpenIM 重构点 | 额外成本(人日) |
|----------|------------------|----------------|
| 实时聊天收发 | 自建消息通道/协议 | 含在 P0 信令层(20-30) |
| 历史消息 | 自建消息表 + 分页接口 | 4-6 |
| 已读回执 | 自建回执表 + 事件 | 2-3 |
| 在线状态 | 自建心跳/在线判定 | 3-5 |
| 图片/文件/语音 | 自建上传/存储/缩略图 | 6-10 |
| 群聊/广播模式 | 自建会话成员/监听模型 | 5-8 |
| 会话列表未读数 | 自建未读数聚合 | 3-5 |

> **小计（去 OpenIM + 补齐基础实时能力）≈ 35-55 人日**：含框架模块 `Sb.Framework.Chat.Realtime` 开发（15-25）与客服项目接入（20-30），是最主要的重构投入。详见 `05-框架级OpenIM替代方案-模块设计.md`。

## 4. 成本汇总

| 类别 | 成本(人日) |
|------|-----------|
| P0：去 OpenIM，实时信令框架模块 + 项目接入 | 35-55 |
| P1：常用客服功能（快捷回复/关键词/敏感词/报表等） | 22-38 |
| P2：增强（检索/轨迹/忙闲等） | 9-15 |
| P3：进阶（工单/AI/多端） | 30-65 |
| **合计（建议范围内）** | **约 65-105 人日** |

> 注：P1 中不少功能可在去 OpenIM 的后端切换完成前并行开发；工单与 AI 属独立大块，建议单独立项。
