## 二、执行计划（6 个阶段）

### Phase A：后端安全与数据完整性修复（P0）

> 目标：堵住安全漏洞和数据丢失风险，不改变架构。

| 步骤 | 内容 | 涉及文件 |
|------|------|----------|
| A1 | PaymentCallbackController 加签名验证 | PaymentCallbackController.cs |
| A2 | 为 3 个关键多写操作加 `ExecuteInTransaction` | OrderService / MemberService / QuotaService |
| A3 | appsettings.json 密钥改环境变量占位符 | appsettings*.json |
| A4 | AutoSyncStructure 改 false（生产），引入迁移版本表 | appsettings.json + 新建 __migration_history |
| A5 | 修复 Distinct().Count() bug | QuotaService.cs:327 |
| A6 | 修复 AdminRole 导航属性 bug | AdminRole.cs:33 |

### Phase B：后端架构重做（P1 架构）

> 目标：推倒重做不合理的架构，不保持一致性。

#### B1：ChatAuthService 拆分

```
ChatAuthService (800行, 14依赖) 拆为：
├── VisitorAuthService     — 访客认证 + JWT 签发
├── SessionOrchestrator    — 会话创建 + 分配 + 系统消息
├── SdkResponseBuilder     — SDK 响应格式映射
└── ChatAccessValidator    — 平台/域名/配额校验
```

#### B2：引入 Repository 约束

- Service 仅通过 `_fsql` 操作**自身主实体**
- 跨实体查询改为注入对应 Service
- 移除 219 处跨实体 `_fsql.Select<OtherEntity>()`

#### B3：统一枚举策略

- 全部改为 C# enum + `MapType = typeof(string)`（可读性优先）
- 移除 Order/AutoReply 的 static const 模式

#### B4：统一时间字段

- 全部改为 `CreateTime` + `InsertValueSql = "now()"`
- 移除 C# `DateTime.Now` 默认值

#### B5：实体清理

- 删除 Member 实体中不存在的遗留 DB 列（PaymentPassword/CreditScore/RealNameStatus 等）
- ChatUserId 字段重命名消歧：`ChatUser.ChatUserId`→`ChatUserId`(string Realtime ID)；`ChatUserLoginRecord.ChatUserId`→`ChatUserDbId`(int)
- 实体加 `[Index]` 特性
- ISoftDelete 加 `DeletedAt`/`DeletedBy`
- 修复 ChatUserLoginRecord/ClientErrorLog 不实现 IEntity 问题（long Id → 改为 int Id）

### Phase C：前端核心重做（realtime-core-js）

> 目标：openim-core-js 推倒重做为 realtime-core-js。

| 步骤 | 内容 |
|------|------|
| C1 | 新建 `realtime-core-js/`，基于 `@microsoft/signalr` |
| C2 | 删除 `patchFetchForOpenIM`（全局 fetch hack 不再需要） |
| C3 | 删除 `cacheGuard`/`fixSdkCacheAfterSync`（SignalR 无此 bug） |
| C4 | 删除 `window.__OPENIM_SDK` 调试残留 |
| C5 | 新增 `SessionOrchestrator`：封装 connectAndLogin + waitForSync + offline 通知 + 排队轮询 |
| C6 | composable 改为工厂函数（消除模块级单例） |
| C7 | 包名 `@saibotianlong/realtime-core`，类名 `RealtimeClient` |
| C8 | 补充类型定义（groupID 等缺失字段） |
| C9 | 删除旧 `openim-core-js/` 目录 |

## 三、决策记录（追加）

| # | 决策 | 理由 |
|---|------|------|
| D21 | **ChatAuthService 拆分为 4 个 Service** | 800 行 14 依赖的上帝类不可维护 |
| D22 | **引入 Repository 约束，Service 不跨实体查询** | 219 处跨实体 _fsql 造成隐式耦合 |

| D28 | **PaymentCallbackController 加签名验证** | 安全漏洞 |
| D29 | **关键多写操作强制事务** | 数据一致性 |
| D30 | **ISoftDelete 加审计字段** | 可追溯删除操作 |

## 四、优先级与依赖

```
Phase A (安全修复)  ← 无依赖，立即开始
    ↓
Phase B (后端重做)  ← 依赖 A 完成
    ↓
Phase E (DB 重设计) ← 与 B 并行，B 完成后执行
    ↓
Phase C (前端核心)  ← 与 B/E 并行
    ↓
Phase D (前端 UI)   ← 依赖 C
    ↓
Phase F (回归清理)  ← 依赖全部完成
```

可并行：B+E+C 三路同时推进。
